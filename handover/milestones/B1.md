GOAL
Port the Node builder to PHP so it produces the same site. The PHP output must pass a
parity comparison against the Node output. Do NOT build the editor or publishing.

WHAT YOU NEED FROM THE OWNER (ask first, with "PLEASE PASTE:")
    site\build.js   (the owner pastes it in parts)
    site\src\templates\layout.html
    site\src\templates\sections\page-hero.html
    site\src\templates\sections\rich-text.html
You do not need the other templates; they are only rendered, not interpreted.

BUILDER RULES (must match build.js exactly)
    1. Escaping: a custom escape callback that replaces ONLY & < > " ' with
       &amp; &lt; &gt; &quot; &#39;. Never touch "/".
    2. Templates: .html files; sections in templates/sections/, partials in
       templates/partials/ (header, drawer, footer, bottom-nav), layout in
       templates/layout.html.
    3. Section data: source file merged with inline data (data wins), then filter and
       excludeSelf on "items", skip sections with enabled=false, sort by order.
    4. addFlags: for every array at any depth, add a sibling key has_<name> that is
       true when the array is not empty. This is what templates use to wrap lists.
    5. Page extras: page.crumbs = breadcrumbs with a boolean "last" on the final
       item; the view also gets site, nav, page, body, canonical, ogImage, jsonld,
       year, buildId.
    6. JSON-LD: Organization (ProfessionalService), WebSite, WebPage, BreadcrumbList,
       FAQPage (from enabled faq sections), Service (when page.service exists),
       Article (when page.article exists). Output with JSON_UNESCAPED_SLASHES and
       JSON_UNESCAPED_UNICODE; remove null values.
    7. Paths: "/" is index.html; "/a/b/" is a/b/index.html; "/404.html" stays a file.
    8. SEO files: sitemap.xml (skip indexable=false pages), robots.txt, llms.txt.
    9. Static and assets copied on full rebuild; sw.js has __BUILD__ replaced by the
       build id.
    10. Isolation: a section that throws is skipped and logged; a page that throws is
        skipped and logged; the build continues.
    11. The builder never deletes unknown files; it records generated files in
        generated.json (location per H01 section 6) and uses atomic writes.

STEPS
STEP 1. Package and smoke test
Ask the owner to run "composer require mustache/mustache" and
"composer show mustache/mustache", and to paste the relevant options from
vendor\mustache\mustache\src\Engine.php (give a PowerShell Select-String command
that searches for: escape, loader, partials_loader, entity_flags, strict_callables).
Then deliver tests/Unit/MustacheSmokeTest.php proving, on this PHP version: the
custom escape rule, partials, the implicit iterator {{.}}, and section-over-array
behaviour with a has_* flag.
Checkpoint: "php artisan test --filter=MustacheSmoke" passes on PHP 8.5.
If it does not, STOP and ESCALATE.

STEP 2. Plumbing
AtomicWriter (temp file then rename, creates folders, stays inside the output root,
rejects ".." in paths), ContentRepository (read-only: reads site.json, nav.json,
pages/*.json, shared/*.json with clear exceptions), and unit tests.
Checkpoint: php artisan test.

STEP 3. Section rendering
SectionRenderer with rules 3, 4 and 10, and unit tests for: source merge, filter,
excludeSelf, enabled=false, ordering, addFlags nesting, and isolation of a failing
section.
Checkpoint: php artisan test.

STEP 4. Structured data and SEO files
JsonLdFactory and SeoFilesWriter with unit tests (one test per schema type; the
sitemap excludes indexable=false pages).
Checkpoint: php artisan test.

STEP 5. SiteBuilder and the build command
SiteBuilder assembles pages (rules 5, 7, 9, 11) and the artisan command
"cdrwa:build" with options --data=, --out= (defaults from config) and --full (copy
static and assets).
Checkpoint: owner runs "php artisan cdrwa:build --full --data=<seed path>
--out=C:/laragon/app/cdrwa-app/site-out" and pastes the output; then lists the
files in site-out (give the PowerShell command).

STEP 6. Parity command
"php artisan cdrwa:parity --golden=<dir> [--data=<dir>]". It builds into
storage/app/cdrwa/parity-out using the SEED data (default CDRWA_SEED_DATA_PATH, never
the editors' live data), then compares every file in the golden folder with the PHP
result. Before comparing it normalises:
    - line endings (CRLF to LF)
    - the build id in "?v=" query strings and in sw.js
    - runs of whitespace between tags, and leading/trailing whitespace
It prints PASS, or lists every differing, missing or extra file with the first
differing normalised line (up to 200 characters each). Exit code 1 on any difference.
It must not ignore anything else.
Checkpoint: the owner runs "npm run build" inside site\, then
"php artisan cdrwa:parity --golden=site/dist" and pastes the full output.

STEP 7. Close the gap
Use the parity report to fix differences, one group at a time, until the report says
PASS. If a difference comes from a template feature that Mustache for PHP and for
JavaScript handle differently, do NOT edit the templates. Stop and report it as a
deviation so the senior can rule on it.

ACCEPTANCE

(running it twice gives identical output); no file outside the output folder is
